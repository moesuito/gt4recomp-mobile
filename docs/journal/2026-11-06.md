# 2026-11-06

- **Private Android build rc15: GSdx (ARMSX2) by default, the PC GSdx experience, textures through the phone's picker.**
  Android now starts on GSdx (ARMSX2); CoreGS 2.0 is the second choice and a chosen renderer is kept. The separate
  ARMSX2 resolution row is gone: the shared Render scale (percentage of the screen's height, the PC's model) sits under
  the Renderer, feeds both renderers and snaps to ARMSX2's own multipliers (1x, 1.25x .. 6x). A fresh install reads the
  screen at start-up and lands on the 2x default (83% · 2x · 1280x896 on a 1080-high screen; 62% · 2x on the S23). The
  Performance HUD row shows with GSdx (ARMSX2) again and the library really receives it (`GT4_ARMSX2_GS_HUD=full`,
  "HUD full" in the VSync lines); a heading with no visible row is no longer drawn.
- **Texture replacement** (owner's request): "Escolher pasta…" opens the system folder picker (SAF, persistable); the
  picked tree is copied once into `<data>/data/textures-sync` because the ARMSX2 GS reads file paths, never content
  URIs, and the page shows the name in plain words ("Pasta de texturas: GT4-textures (escolhida no celular)"). The
  layout is PCSX2's: `<serial>/replacements` (a folder holding `replacements` at its top is nested under the serial
  after the copy). `armsx2-gs.ini` gets `[Folders] Textures`, `LoadTextureReplacements = true` (owned by the Custom
  textures row), `LoadTextureReplacementsAsync = true` and `PrecacheTextureReplacements = true`; the library logs the
  folder and the file count at start. In the emulator a self-made 4-PNG pack was picked and `game.log` shows
  `4 replacement files under .../SCUS-97328/replacements`.
- **Names like the PC:** versionName `1.3.0-rc15` (footer, General page, logs, Android app info), versionCode
  `103001500 + build number` = 103001501, file `GT4Recomp-1.3.0-rc15-mobile-arm64.apk` (143,919,214 bytes, sha256
  `71ec60d8...5df5a97`), owner's release key, `zipalign -c -P 16` clean. The old test4-named APK and `.sha256` were
  deleted; `symbols/libgt4gs-unstripped.so` refreshed.
- **Vulkan and FSR1:** still absent. The Android ARMSX2 build links a `shaderc` target, but the local tree has no
  `3rdparty/shaderc`, glslang, SPIRV-Tools or SPIRV-Headers and no pinned revisions for them; fetching and building all
  four for arm64 was left for a dedicated round, so OpenGL ES stays the back end and FSR1/SGSR stay unoffered.
- **Checks:** `cargo test -p gt4l-core` green; `cargo test -p gt4l-tauri --lib -- --test-threads=1` 146 passed. In
  parallel, two flow_audit tests interfere with each other (seen with `a_1_2_x_install...` and
  `an_install_with_a_copy...`); both pass alone and the whole suite passes serially.
